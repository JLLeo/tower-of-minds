# 每个 Agent 独立调用 LLM，不合并成批量调用

一场 Encounter 里的每个 Agent 每回合各自发起一次 LLM 调用（并行），而不是用一个 "指挥官 prompt" 一次性产出全队 Intent。批量调用更省钱也更省延迟，但它会让 Agent 之间的协作、抢功和内讧变成同一个大脑的独白——玩家分辨不出那是几个心智，而"多个心智彼此有关系"正是这个项目要卖的东西。

写下这条是因为它看起来像一个明显的优化点：后来的人几乎一定会想把 N 次调用合并成 1 次。那不是优化，那是把产品砍掉。

## Consequences

同场 Agent 数量受延迟和成本约束，切片阶段定在 2–3 个。降低成本要从模型档位和 prompt 长度上想办法，不要从合并调用上想办法。
